# 研究型多轮对话记忆设计

## 目标

让 Paper Agent 能在同一会话及跨会话中延续用户的论文阅读、实验复现和小论文写作工作，同时积累可纠正的研究者画像。系统必须把“理解用户意图的记忆”和“回答论文事实的证据”严格分开。

## 范围

第一期覆盖：

- 解析省略和指代，例如“它”“这个方法”“第二个贡献”“如何复现”。
- 在明确选择、检索或切换论文后维护会话焦点。
- 保存当前研究任务、待解决问题、最近对话和滚动摘要。
- 自动提炼并静默更新学习情况、研究方向、课题和研究进度。
- 允许用户在自然语言对话中直接纠正或覆盖记忆。
- 记录记忆的来源、置信度、更新时间和历史版本。

第一期不引入知识图谱、跨用户共享记忆或把整段聊天嵌入 Milvus。

## 四层数据模型

| 层级 | 存储 | 内容 | 用途 |
| --- | --- | --- | --- |
| 会话焦点 | MongoDB `sessions` | `active_paper_ids`、`active_section`、`active_task`、`open_questions` | 消解当前对话中的指代与省略 |
| 对话上下文 | MongoDB `sessions` | 最近原文消息、滚动摘要、摘要覆盖的消息范围 | 在 Token 预算内保持多轮连贯 |
| 研究者档案 | MongoDB `user_memory` | 学习情况、研究方向、研究项目、阶段、里程碑、偏好 | 跨会话理解用户的研究背景 |
| 论文证据 | MongoDB/Milvus | 论文元数据、原始 chunks、向量和章节 | 为论文事实生成答案与引用 |

会话和研究者档案不能作为论文事实的来源。所有“论文提出了什么、实验如何设置、结果是多少”的回答，必须仍由检索到的论文 chunks 支撑。

## 上下文决策与数据流

1. 前端显式选择论文时携带论文 ID；后端将其设为会话焦点。
2. 用户明确提及另一篇论文、选择论文库条目，或完成新的论文获取时，更新焦点并保留切换记录。
3. 没有明确切换且问题属于追问时，工作流将会话焦点中的论文和任务带入 `AgentState`，不依赖标题正则猜测。
4. 上下文构建器提供“会话焦点 + 最近若干轮原文 + 滚动摘要 + 必要的研究者档案”，供 Supervisor 和分析 Agent 使用。
5. 回答完成后，异步记忆提炼器从本轮对话提出候选更新，并按合并规则写入 MongoDB；提炼失败不影响本轮回答。
6. 用户出现明确修正表达（如“不是这样”“改为”“我现在的方向是”）时，提炼器生成覆盖更新；旧值保留为历史版本。

## 自动提炼和合并规则

- 只写入与学习状态、研究方向、研究项目、研究进度、待办和长期偏好有关的信息。
- 每条记忆包含 `value`、`source_session_id`、`source_message_ids`、`confidence`、`updated_at` 和 `status`。
- 明确的用户陈述可覆盖同一字段的旧值；模型推断只能新增低置信候选或推进已有任务，不能无来源地改写研究方向。
- 自相矛盾或低置信候选不覆盖已确认数据，保留为待观察项。
- 用户可以在对话中要求查看、修改或删除档案；后续界面可直接展示和编辑相同字段。

## 错误处理

- 找不到会话焦点的论文时，清除失效焦点并提示用户重新选择，不下载无关论文。
- 记忆提炼或数据库写入失败时记录日志、跳过本轮更新，核心问答继续完成。
- 摘要生成失败时仅使用最近原文消息，不阻塞会话。
- 焦点不明确且问题无法可靠解析时，优先提出澄清而非把任意旧论文当作目标。

## 验收标准

- 从论文库选择论文后，连续追问“它的实验怎么复现”“第二个贡献是什么”，不会重新以中文追问搜索 arXiv。
- 会话中明确切换另一篇论文后，后续“它”指向新论文。
- 重启服务后恢复相同会话，焦点和必要上下文仍生效。
- 对话提及用户研究方向或任务进展后，档案可静默更新且保存来源；用户更正后新值在下一轮生效。
- 论文结论类回答仍附有论文 chunk 证据，且不会引用用户档案或聊天摘要作为论文依据。
- 自动化测试覆盖焦点延续、显式切换、失效焦点、记忆覆盖与提炼失败不阻断回答。
