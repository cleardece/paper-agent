# 可恢复研究图谱任务设计

## 目标

将研究图谱从 Web 进程中的无界线程调用，改为可终止、可恢复、可观察的后台任务系统。所有已经完成索引的论文都应最终得到同版本的图谱结果；图谱失败不得阻塞 PDF 上传、普通 RAG 或后续论文。

## 触发规则

图谱任务只由以下事件创建或重新排队：

1. 新论文状态原子更新为 `indexed` 后，创建高优先级新论文任务。
2. 服务启动时对账全部 `indexed` 论文；缺少当前 `graph_version` 的论文创建低优先级回填任务。
3. 提取器版本升级时，旧版本自动关系进入重建队列；人工确认关系保留。
4. 用户对失败任务执行手动重试时，创建新的执行轮次并保留历史尝试。
5. 服务启动或轮询发现任务租约过期时，回收并继续调度。

聊天查询不现场生成图谱。没有当前版本图谱时继续使用普通 RAG。

## 状态机

```text
pending
  ↓ 原子领取并写入租约
extracting
  ├─ 有有效关系 → completed_with_edges
  ├─ 无目标关系 → completed_empty
  ├─ 首次失败 → retry_wait
  ├─ 再次失败 → failed
  └─ 租约过期 → pending 或 failed
```

任务保存 `graph_version`、优先级、执行轮次、尝试次数、`worker_id`、租约到期时间、心跳时间、下次重试时间、诊断信息及尝试历史。

## 执行隔离

每次 LLM 提取由独立 Python 子进程执行。父工作者通过标准输入传入经过清理的论文与 chunk JSON，通过标准输出接收结构化结果。父工作者掌握单调时钟截止时间；超时后终止并等待子进程退出，保证挂起的网络请求和线程一并释放。

默认单篇硬超时 120 秒。该值可通过 `GRAPH_EXTRACTION_TIMEOUT_SECONDS` 配置。父工作者定期续租；服务崩溃后租约自然过期并被新工作者回收。

## 调度与熔断

只有 PDF 队列不存在 queued/parsing/chunking/indexing 任务时才领取图谱任务。优先级依次为手动重试、新论文、存量回填。

首次失败进入 `retry_wait`，不会立即占住队首；工作者继续处理其他可运行论文。连续三次基础设施错误后开启五分钟熔断，暂停领取新图谱任务，并在页面展示暂停原因。任一成功请求会清零连续失败计数。

## 零关系诊断

`completed_empty` 不是普通成功。任务保存：选中 chunk 数、模型候选数、提取器拒绝数、证据校验拒绝数和结果原因。页面区分：

- 模型明确返回空数组；
- 模型输出无法解析；
- 候选被字段校验拒绝；
- 候选被原文证据校验拒绝。

## API 与界面

状态 API 返回覆盖论文数、各任务状态、关系总数、熔断状态。任务列表 API 返回每篇论文的当前状态、版本、错误、诊断和尝试历史。失败任务提供手动重试接口；页面展示“索引后自动入队、PDF 空闲时处理”的触发说明。

## 数据安全

重建只删除当前论文的自动关系，不删除 `confirmed` 关系。图谱任务失败不修改论文 `indexed` 状态，不删除 chunk、Milvus 向量或原始 PDF。
