# 研究论文 Agent：准确性与作品集化改造设计

## 目标

将 Paper Agent 打造成长期服务研究生论文阅读与小论文写作的研究助手：回答必须可追溯到已入库论文证据，并具备可复现部署、可量化评测和可观测执行过程。它同时应能作为 Agent 工程实习的真实项目作品。

## 非目标与兼容边界

- 不重写现有聊天、搜索/入库和论文库的基本操作逻辑。
- 不迁移或删除现有 MongoDB、Milvus、缓存或论文数据。
- 不把“快速但未经证实的回答”作为默认行为；准确性优先于响应速度。
- 不为演示而增加脱离真实研究流程的一次性功能。

## 方案选择

采用“作品集强化版”而非纯算法评测或纯前端美化：工程、准确性和界面三者均服务于真实研究使用。

## 准确性与证据约束

1. 回答使用的每个引用均应关联已检索片段的论文、章节或分块编号，并展示其相关性分数。
2. 质量门先执行可确定的校验：引用论文是否在检索结果中、引用标记是否可解析、回答是否在无检索证据时拒绝作答。
3. LLM Critic 继续用于语义审核，但不能作为唯一正确性保证；规则校验失败时应要求重检索或返回“证据不足”。
4. 检索为空、证据不足或质量校验失败时，回答应说明限制并建议下一步，而不能补全推测。

## 评测与可观测性

维护可扩展的 JSON 评测集，包含问题、期望论文、关键词和是否应拒答。提供独立命令输出：

- Recall@K；
- 引用覆盖率与引用存在性；
- 无证据拒答率；
- 分 Agent 和端到端延迟。

每次请求记录 Agent 状态、耗时、检索数量、重试原因和质量门结论。Web 端展示这些数据，但技术细节默认折叠。

## 前端体验

界面保留现有页面和流程，采用现代 AI 产品风格：

- 浅色/深色主题可切换，主题偏好持久化；
- 使用统一颜色、间距、字体、圆角和状态色变量；
- 完善加载、空结果、网络失败、证据不足等状态；
- 回答旁提供可折叠证据面板，展示来源论文、片段、章节/分块与分数；
- Agent 时间线改为可读的可观测面板，而非仅显示步骤名称。

## 可复现工程交付

- 新增根目录 README，涵盖架构、运行前提、快速启动、评测、常见故障和数据边界。
- 使用 `.env.example` 取代对本机密钥与路径的隐含依赖。
- 将 Docker 卷路径参数化，移除固定磁盘盘符依赖。
- 将直接运行所需依赖完整且可复现地声明；提供开发/测试依赖说明。
- 忽略下载 PDF、运行缓存和本地环境，不纳入求职作品提交。

## 实施顺序

第一阶段完成可移植配置、文档、基础测试和证据/质量门数据模型；第二阶段接入评测与可观测数据；第三阶段精修深浅主题、证据面板和时间线。每阶段都必须保留现有功能，并以自动化测试和最小端到端验证收尾。

## 验收条件

1. 新环境可按文档完成配置并启动服务，且不依赖固定磁盘路径。
2. 核心路由、证据校验与失败降级有自动化测试。
3. 评测命令输出至少一项检索指标、一项引用指标和延迟数据。
4. Web 界面在深浅主题下可读，且能查看回答证据与执行过程。
5. 现有论文搜索、入库、对话和论文库流程保持可用。
